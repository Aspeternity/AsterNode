# 已知问题与阶段边界

## 当前阻断生产使用

1. Stage B 自动化/配置级基线已经稳定，但真实 VPS 的 systemd、IPv4/双栈/IPv6-only、NAT 与 3x-ui T24/T25 尚未完成，因此当前仍不是生产发布版。
2. CI #59 已完成 Bash syntax、ShellCheck、18 个测试项和固定 Xray v26.3.27 服务端/客户端配置解析；这些证据**不能替代真实代理链路**。
3. Stage C 的 UFW/SSH/Fail2ban 尚未验收，因此 Stage B 中记录的 `source_addresses` 目前是访问意图/状态模型，不应被解释为已实现真实网络白名单隔离。
4. Stage D 的正式远程 bootstrap、签名/公钥轮换、完整更新回退、备份恢复与卸载仍未完成。
5. ARM64 资产元数据和固定摘要已记录，但当前 CI #59 的真实 Xray 执行是 amd64；ARM64 必须在对应架构的可恢复 VM/VPS 实测。
6. Target 探测结果只代表运行探测的那台 VPS 当时网络；不会自动选择 Target，也不会自动修改节点。

## 当前安全边界

- 遇到受管 Xray 配置摘要漂移时拒绝静默覆盖。
- 线路来源迁移使用“先加新来源 → 实际验证 → 再删旧来源”，不允许对已有线路机直接整组替换来源地址。
- 删除/轮换凭据会使旧导出失效；服务端 privateKey 不进入线路导出。
- 诊断包默认脱敏、0600、不主动联网、不自动上传。
- 若出现 `NEEDS_RECOVERY`，保留第三方现场，默认不强行覆盖。
